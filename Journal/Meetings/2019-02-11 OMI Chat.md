## Key Discussion Points

> [!note] What was talked about?
> Capture the substance - not a transcript, but the important points, context, and nuance that you'd want to recall later.

- HPIP: unclear how HPIP fits into the discussion. OMI already being done, with data capture through MeasurLink. Model-based definitions coming through from RR - can OMI support this?
- [[RF]] "requirements":
	- CAM-based probing - NX is poor in this area; MSP and SPRINT raised as possibilities.
	- OMI to assist in reducing the need for CMM, via "inspection by inference":
		- Measure tool at start and end of machining.
		- Measure faces to infer other components.
		- A control plan is needed, linked to MeasurLink.
		- Confidence in the end-of-machining mini-probe cycle - could potentially eliminate this ~30-minute cycle by inferring measurements instead. [[Mark]] and [[Peter]] (on the agenda for the next call) can inform on this; control plan for parts is key.
		- Less inspection but more data points; CMM is a bottleneck - need a strategy for overcoming this.
	- Tool data capture (length) - measure cuts.
	- Speeding up probing time - work from ADG2268 and MP2.3 OMI; false triggering is an issue on DMG 125s.
	- Machine health monitoring.
	- Broken tools, measure cuts - OMI informing that semi-finish is oversize could indicate a broken tool that an operator (running 1:4 machines) might not have noticed; possible to add logic to programs to measure tool if oversize is detected.

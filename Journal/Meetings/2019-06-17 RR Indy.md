## Key Discussion Points

> [!note] What was talked about?
> Capture the substance - not a transcript, but the important points, context, and nuance that you'd want to recall later.

- [[JS]] gave an overview of Full Monty and the upcoming ABG project.
  - [[Gail Plush]] asked how long the project is and whether the sensor list is being pared down to a manageable set - project expected to wrap up in December/January, and yes, sensor list paring-down was confirmed (had been omitted from the overview).
- [[RH]] gave an overview of the web apps he's developed and his approach.
  - Factory dashboard: emphasis on customisable "takeaway" cards - users choose which cards to see, and new cards can be developed and swapped in.
  - NC Reporter: general demo via videos. RR questions covered data management (validation, flexibility across different data streams/rates, database performance - SQL vs NoSQL, Parquet, flexibility vs performance trade-offs), input standards (MTConnect, OPC UA/DA and others covered; work with Kepware summarised; challenge that differing standards won't go away without machine tool builders adopting a unified approach), the software approach (Flask - small, facilitates a modular approach), and whether Power BI or similar had been considered.
- RR's own work: mostly focused on OEE.
  - 12 Makino machines, with new machines coming in (unclear if capability of new machines from a data perspective has been specified).
  - Makino provided an adapter and agent.
  - Hertzler GainSeeker (SPC software) used for data pull and storage.
  - Changes in state are the main interest, checked on a 5-second period (e.g. running-to-idle transitions update part count and real-time status).
  - Starting to look at capturing more, e.g. changes in override; machine connectivity remains the current priority.
  - Custom Python scripts drive both back- and front-end.
- Question around bringing Quality data together - RR are really interested in this; overview given of a KTP with CWF.

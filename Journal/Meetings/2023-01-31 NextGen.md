## Purpose

- To drill down into the technical architecture for Fourjaw data flow between Fourjaw, AMRC, and Razor.

## Key Discussion Points

- Three potential architecture iterations considered: (a) Fourjaw Machinelink with Factory+; (b) bulk data output for hackathons; (c) real-time output of Fourjaw data.
- Option (a) is not progressing further at the moment, though could be investigated further.
- Option (b) is the current favourite.
- Option (c) is not feasible - Fourjaw unable to support it due to the work involved and other commitments.
- [[Ryan Diver|RD]] noted AMRC placed a large PO with Fourjaw (FJ) on the basis that an API was/would be available; [[RH]] not sure this was actually the case.
- Fourjaw uses a Mongo database. [[Ryan Diver|RD]] proposed looking at how to expose just a subset of Fourjaw data for the customers currently signed up.
- Streaming data is useful to the data champions as part of the learning process.
- A middle-ground streaming approach seems doable via an API.

## Decisions

- Option (b) - bulk data output for hackathons - is the current favoured architecture approach.
- Real-time streaming (option c) is ruled out for now due to Fourjaw's capacity/commitments.
